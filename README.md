# 订单与支付双表对账

仓库 `data/` 下有两份样例数据：`orders.csv` 是订单状态记录（`order_id,status,amount,updated_at`，时间戳为运营系统落库的北京时间），`payments.csv` 是支付流水（`pay_id,order_id,amount,paid_at`，时间戳为 UTC）。本仓库实现 `reconcile.py`：两侧各自算日粒度实收 GMV 与日环比，产出「日 × 订单」粒度的对账差异与归因分类。

## 运行

环境：Python 3 + pandas（不用 Docker）。脚本从仓库根目录运行，默认读 `data/`。

```bash
python3 reconcile.py                     # 输出到当前目录
python3 reconcile.py --outdir out        # 指定输出目录
python3 reconcile.py --orders data/orders.csv --payments data/payments.csv
```

样例数据结果（2026-10-01 ~ 2026-10-30，30 天）：

| 指标 | 金额（元） |
|---|---|
| 订单侧实收 GMV | 150301.68 |
| 支付侧实收 GMV | 157248.00 |
| 差异净额（订单 - 支付） | -6946.32 |
| 差异绝对值合计 | 18191.02 |

对不上 76 条（日 × 订单）：时区窗口差 32 条、退款或负向冲抵 9 条、重复或多状态行 13 条、其余未对上 22 条。

## 口径

### 时间

- 订单表 `updated_at` 无时区标记，按北京时间直接取日历日。
- 支付表 `paid_at` 带 `+00:00`，先换算到 `Asia/Shanghai` 再取日历日。两侧由此统一到北京时间的「日」。
- 日历取两表日期的并集区间，缺数日按 0 补，两侧用同一日历，便于逐日比较。

### 订单侧：状态机定最终状态

同一订单可能有多行状态（下单、改价、取消），时间戳偶有乱序，因此**不按最新时间戳取最终状态**，而按状态机优先级：

```
成交(3) > 改价(2) > 下单(1) > 取消(0)
```

每个订单取优先级最高的那一行作为最终状态行；同优先级下才用 `updated_at` 兜底排序。只有最终状态为「成交」的订单计入实收，金额取最终状态行的金额（改价后的订单净额，即财务口径的实收）；负金额的成交行按净额冲抵计入。

### 支付侧

每笔支付按换算后的北京日期计入当日实收，同一订单的多笔支付（分笔付款）自然累加。

### 日环比

对两侧分别输出每日 `gmv`、`mom_amount`（当日 - 前一日，元）与 `mom_pct`（`mom_amount / |前一日| * 100`，保留 2 位）。首日无前一日、或前一日为 0 时环比留空（无法定义）。

### 对账单元

按「日期 + 订单号」汇总两侧金额：`order_amount`、`payment_amount`、`diff_amount = order_amount - payment_amount`。凡 `diff_amount != 0` 的单元都写入 `diff.csv`，包括只有一侧有数的单元（另一侧记 0）。

## 差异归因（四类互斥，每行恰好一类）

判定按下列顺序执行，命中即止：

1. **时区窗口差**：支付行按 UTC→北京换算后跨了日（`paid_at` 的 UTC 日期与北京日期不同），且同一订单在换算前的 UTC 日期那一格存在金额相同、符号相反的订单侧记录。两侧成对出现，净额为 0，属于日界归属差，不是真金白银的缺口。
2. **退款或负向冲抵**：该单元订单侧或支付侧金额为负（退款、冲抵只记在一侧或两侧符号不一致）。
3. **重复或多状态行**：
   - 支付重复：`pay_id` 重复，或同一订单同一时刻同一金额出现多行；
   - 多状态行：订单有下单/改价记录但从未成交，订单侧不计实收而支付侧有款。
4. **其余未对上**：上述都不成立的真实缺口，例如支付表有单而订单表无此订单、成交订单没有支付、订单已取消但仍收到支付款、分笔付款跨多日导致的日切错位。

样例数据上的分布：时区窗口差 32 条（净额 0）、退款或负向冲抵 9 条（净额 -2634.26）、重复或多状态行 13 条（净额 -2956.67）、其余未对上 22 条（净额 -1355.39）。

## 输出文件

| 文件 | 内容 |
|---|---|
| `orders_daily.csv` | 订单侧日粒度：`date,gmv,mom_amount,mom_pct` |
| `payments_daily.csv` | 支付侧日粒度：同上 |
| `diff.csv` | 差异明细：`date,order_id,order_amount,payment_amount,diff_amount,category` |
| `summary.txt` | 两侧口径总额、差异净额与绝对值、四类的笔数与金额 |

金额以元为单位保留 2 位小数；内部按「分」用整数累加，避免浮点误差。分类名固定为 `时区窗口差` / `退款或负向冲抵` / `重复或多状态行` / `其余未对上`。

## 假设与边界

- 输入列名与时间格式按题面固定；金额无法解析、时间无法解析、状态不在状态机中、`order_id` 为空等异常一律抛错并记录日志，不静默跳过（财务数据静默丢行的风险高于中断）。
- `Asia/Shanghai` 无夏令时，等价于固定 +08:00。
- 退款单以负金额行表达；未在数据中出现的「退款单独成表」场景不处理。
- 重复支付的判定只覆盖 `pay_id` 重复与「同订单同时刻同金额」两种形态；金额不同、时间不同的分笔支付视为正常拆分。
